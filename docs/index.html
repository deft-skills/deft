About DEFT
Metamodel · Checks · Generator · Catalogue

DEFT

Engineer agent skills as software. DEFT lets you specialize skills into families, compose them into typed workflows, check both before any agent runs, and generate plain SKILL.md files that follow the Agent Skills specification.

Quickstart Read the guides Browse the catalogue

Why

Agent skills are folders of instructions that coding agents load on demand. The specification fixes a few metadata fields and leaves skills unrelated, so libraries grow by copying: a shared procedure is pasted into every variant, and pipelines are described in prose ("then use skill X"). Copies drift, and a pipeline that wires two incompatible skills fails only while an agent runs it.

⊑

Specialization

Skill families. A parent holds the procedure every variant shares; variants fill its variation points or change its defaults, and DEFT records where every instruction comes from.
→

Composition

Workflows whose steps exchange typed artifacts, invoke other skills, repair failures a bounded number of times, and declare pre- and postconditions.
✓

Checks

Hierarchies, bindings and data flow are validated before execution. A variant that accepts a narrower input is fine in its family and rejected where it is wired to an incompatible step.
▤

Plain skills out

Every model generates standard skill folders, with inputs, outputs, conditions, provenance and the licences of reused material. Agents need nothing new.

How it works

  1. Model

    Describe artifact types, skill families and workflows in YAML. Writing models.

  2. Check

    deft check models validates both hierarchies, every refinement, binding and edge. Validating models.

  3. Generate

    deft generate models --out skills writes one folder per concrete skill and workflow. Generating skills.

  4. Run

    Install the folders in any compatible agent and ask it to use a workflow. Using generated skills.

The example library

DEFT ships with a library that delivers a feature request with a spec-driven process, built on public skills from Spec Kit, Superpowers and anthropics/skills: requirements in several notations, planning, test-driven implementation, acceptance and performance tests, and bounded repair. Its main workflow, deliver-feature:

flowchart TB
  in((start))
  functional["specify-functional<br/><b>user-stories</b>"]
  quality["specify-quality<br/><b>volere</b>"]
  plan["plan-feature"]
  implement["execute-plan<br/><b>execute-plan-inline</b>"]
  tdd["test-driven-development"]
  acceptance["acceptance-tests<br/><b>acceptance-gherkin</b>"]
  performance["performance-tests"]
  verdict{verdict}
  debug["systematic-debugging"]
  done(((end)))
  in -->|FeatureRequest| functional
  in -->|FeatureRequest| quality
  functional -->|Requirement| plan
  quality -->|Requirement| plan
  plan -->|ImplementationPlan| implement
  functional -->|UserStory| acceptance
  implement -->|SourceCode| acceptance
  quality -->|MeasurableQualityRequirement| performance
  implement -->|SourceCode| performance
  acceptance -->|TestReport| debug
  performance -->|TestReport| debug
  implement -->|SourceCode| debug
  implement -.->|invokes| tdd
  acceptance --> verdict
  performance --> verdict
  verdict -->|every report has verdict pass| done
  verdict -->|some report has verdict fail| debug
  debug -.->|repair ≤3| implement
