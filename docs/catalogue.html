Skills

The example library: 21 skills in 6 families. Concrete skills and workflows are generated as SKILL.md folders; abstract skills exist only in the models and reach agents through their specializations.

Requirements

specify-requirements

Use when a feature request must become a set of uniquely identified, testable requirements before planning or implementation starts.

abstractadapted from github/spec-kit

specify-functional

Use when the behaviour a feature must provide has to be specified as functional requirements.

abstractadapted from github/spec-kit

specify-requirements › specify-functional

specify-quality

Use when the qualities a feature must have (performance, security, usability and similar) have to be specified as quality requirements.

abstractadapted from github/spec-kit

specify-requirements › specify-quality

user-stories

Use when functional requirements must be written as user stories with Given/When/Then acceptance criteria.

concreteadapted from github/spec-kit

specify-requirements › specify-functional › user-stories

ears

Use when functional requirements must follow the EARS (Easy Approach to Requirements Syntax) patterns.

concreteadapted from github/spec-kit

specify-requirements › specify-functional › ears

volere

Use when quality requirements must be written as Volere snow cards with a measurable fit criterion.

concreteadapted from github/spec-kit

specify-requirements › specify-quality › volere

iso25010

Use when quality requirements must be classified by ISO/IEC 25010 characteristics and sub-characteristics.

concreteadapted from github/spec-kit

specify-requirements › specify-quality › iso25010

Planning

plan-feature

Use when validated requirements must become an implementation plan of small, test-first tasks before any code is written.

concreteadapted from github/spec-kitadapted from obra/superpowers

Implementation

execute-plan

Use when an implementation plan exists and its tasks must be implemented and committed one by one.

abstractadapted from obra/superpowers

execute-plan-inline

Use when the plan must be executed task by task in the current session, or when no subagent tool is available.

concreteadapted from obra/superpowers

execute-plan › execute-plan-inline

execute-plan-subagents

Use when the plan must be executed by a fresh implementer subagent per task, each followed by a task review.

concreteadapted from obra/superpowers

execute-plan › execute-plan-subagents

test-driven-development

Use when implementing any feature or bugfix, before writing implementation code.

concreteimported from obra/superpowers

Verification

generate-tests

Use when requirements must be verified against an implementation with executable tests traced to requirement ids.

abstract

acceptance-tests

Use when user stories must be verified end to end through their acceptance criteria.

abstract

generate-tests › acceptance-tests

acceptance-gherkin

Use when acceptance criteria must become Gherkin feature files executed with pytest-bdd.

concrete

generate-tests › acceptance-tests › acceptance-gherkin

acceptance-playwright

Use when acceptance criteria must be checked through the user interface of a web application with Playwright.

concreteadapted from anthropics/skills

generate-tests › acceptance-tests › acceptance-playwright

performance-tests

Use when measurable quality requirements (response time, throughput, load) must be verified with load tests.

concrete

generate-tests › performance-tests

systematic-debugging

Use when encountering any bug, test failure, or unexpected behavior, before proposing fixes.

concreteimported from obra/superpowers

quantify-quality

Use when quality requirements without an objective metric must be made measurable before they can be tested.

concrete
